# Research: 131 MDX cube facts

Measured on iris-dev-iris (`iris-community:2026.2`), namespace USER, on 2026-09-29. The claims are quoted from PR 142's `skills/skills/iris-mdx/SKILL.md` at 7f9b71c.

## Probe

T001 passed. `%DeepSee` builds a cube in USER on community 2026.2. I put and compiled the three fixture classes and wrote the 8 rows. `%BuildCube("IadLive131Sales",0,0)` and `%BuildCube("IadLive131Other",0,0)` both returned OK, and `SELECT FROM [IadLive131Sales]` returned 8.

The probe also turned up two iad bugs:

1. **`sa_schema` never returned a grammar for any URL.** iad encoded the whole name as one path segment, `/saschema/http%3A%2F%2Fwww.intersystems.com%2Fdeepsee`, and Atelier answers that with 404. It wants the slashes raw: `/saschema/http%3A//www.intersystems.com/deepsee` returns the 6,755-byte grammar, and v1 of the API returns 404 for either form. Before 131, a correct call and a cube name failed the same way, with an empty `result`. `sa_schema_path` now encodes each segment and keeps the slashes, and `the_url_keeps_its_slashes_in_the_path` covers it.
2. **Embedded SQL with `INTO` failed inside `iad exec`.** `&sql(SELECT COUNT(*) INTO :n FROM IadLive131.Sale)` failed with `<PROPERTY DOES NOT EXIST> COUNT(*),%sqlcq.USER.cls171`, and the same query through `%SQL.Statement` worked. IRIS was not the cause. iad's 035 translator rewrote every `&sql` to `%SQL.Statement` before it chose a path, and read each host variable with `%Get("<column text>")`, so `COUNT(*)`, `TOP 1 Name` and any expression failed. It also set `SQLCODE` only when no row came back, never for DML, and emitted an `if ... {` block that the docker path's own guard refuses. The HTTP path compiles the code into a class method, where IRIS expands `&sql` natively: a probe class with the same `&sql` in a `[ SqlProc ]` method returned `code=0 n=858`. 131 US5 sends `&sql` untranslated over HTTP and keeps the translation for docker exec only, where it now reads by position, sets `SQLCODE`, `%msg` and `%ROWCOUNT`, and has no braces. `test_exec_sql_131_live` checks both paths; the docker DML case on a missing table gives `-30`.

## Fixture

`crates/iris-agentic-dev-core/tests/fixtures/mdx131/README.md` has the rows, the dimensions and the hand totals. Each live test builds the fixture, runs its queries, tears down, and then asserts that `%Dictionary.ClassDefinition` has no `IadLive131.*` class left (SC-004). A full run of the 17 tests takes about 21 s.

The fixture's first design used Channel, with a `rangeExpression`, as the integer-keyed level. On IRIS the mapped name becomes the key, so Channel is keyed by caption. The integer-key claim is measured on Doctor instead, whose key is the id and whose caption comes from a `Name` property.
