## Remaining items

- **List patterns §1.** WRONG and "CORRECT for CSV" are the same loop, and the WRONG label is backwards. Timed live: `Set lst=lst_$LB(i)` builds 80,000 items in 0.002 s and 20,000 in 0.0006 s (linear). `Set $LIST(lst,*+1)=i` takes 1.71 s and 0.11 s (quadratic). Both produce the same list. Fix: concatenation is the fast form; `$LIST(lst,*+1)` is the one to avoid in a hot loop.
- **SQL naming.** The §1 rule reproduces: `Test127.Ext` → SQL `Test127.Ext` (SQLCODE 0), `Test127_Ext` → -30. `Test127.Sub.Deep` → `Test127_Sub.Deep` (0), `Test127.Sub.Deep` → -30. §§2, 4, 5, 9 use `Catalog_Item`, `Config_Setting`, `Bench_Patient` for two-level classes, which the rule says fail.
- **ensemble-production Storage.** #5477 reproduces, but at compile time, not runtime: `Keyword signature error in Test127.Msg:Storage:Default, keyword 'DataLocation' must be '^Ens.MessageBodyD'`. The fix drops the hand-written "Right" Storage block and says to leave Storage to the compiler.
- **ensemble-production 31-character limit (new).** False. `Test127.VeryLongPackageName.Data.PatientRecordHistory` compiles and saves; IRIS hashes the global to `^Test127.VeC343.PatientReco5843D`. The "rename it" advice goes.
- **Production restart.** Needs a live production with queued messages. Reproduced in the implementation phase, before its edit (FR-001).
- **`iris_compile` and local paths.** Mixed, and the server instruction is the party that is wrong for the HTTP path. `iris_compile` in `tools/mod.rs` treats any target containing `/` or `\` as a local file, reads it and uploads it by Atelier PUT before compiling. On the `docker_only`/NoPWS path the target string goes straight into `$SYSTEM.OBJ.Compile`, so a path fails. `iris_compile(target="*.cls")`, which `iris-objectscript-eval` says compiles "all .cls files in workspace", is a server-side wildcard over the namespace. FR-005 stands: skills push with `iris_doc(mode="put", compile=true)`, which works on both paths. The server instruction's "it never reads local files" is false and is recorded as a follow-up; the server instruction is out of scope for 127–130 (grill Q12).
- **iris-docs DocBook.** `curl -A "$UA"` on `DocBook.UI.Page.cls?KEY=GCM_monitoring` returns HTTP 200, 311 KB, title "Version Not Available", no body text, and the five `ALG-*` meta tags. So "curl gives a nav shell" is true and the re-scrape recipe is also right: it reads the shell's meta tags, not the content. The "often a 504" was not seen. Fix: one rule stating both.
- **aihub-eap.** Upstream is `intersystems-community/ai-hub-eap` `skills/aihub-eap/SKILL.md` at blob `72f9046`. Vendored copy differs by 257 diff lines: `@{env.}` vs `@{env:}`, `grok` vs `xai`, upstream's `managed_by`/`source` front matter, and a whole §12 the copy lacks. Upstream still has the precedence bug at line 148. Live: with `p="abc",c="X"`, `p = "" && c '= ""` gives 1 and `(p = "") && (c '= "")` gives 0, so `%OnInit` overwrites a provider the caller set. `skills-lock.json` is gitignored, so the committed hash check lives in a test fixture, not the lock.

## Item 9: quoted form unverified

Embedded Python on this instance is broken: `op."add"(1,2)` and `$method(op,"is_not",1,2)` both return `2`, and the next call segfaults the process (`caught signal 11` in `messages.log`). After each segfault the shared routine cache goes bad (`<ROUTINELOAD> *class %SYSTEM.OBJ invalid cache`, "System routine buffer shortage", worker crash loop), and every new session hangs until IRIS restarts. Three restarts were needed on 2026-09-26.

So the unquoted failure is verified. That the quoted form `pyobj."my_function"(42)` works is not verified here. The skill fix states the unquoted failure (verified) and gives the quoted form as the documented fix, naming it unverified on this build. Live tests for item 9 must not call into Python on iris-dev-iris until the Python runtime is repaired, or they take the instance down.

## Hazard for the live test suite

`$system.OBJ.Delete` on a class whose routines sit in a poisoned cache hangs the caller. Live 127 tests run each IRIS step with a timeout and never touch `%SYS.Python`.

Also: `$system.OBJ.ShowFlags()` in a piped terminal session reads the rest of stdin as paging input. Scripts must not call it.
